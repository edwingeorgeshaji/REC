# Edwin George Shaji — design and maintenance specification

Last reconciled with the implementation: 29 October 2026.

## Read this first: handoff to another model or platform

This is the single current design specification, not a chronological changelog. Obsolete source snapshots and contradictory experiments have been removed. Follow the rules below when editing content or extending the site. A later explicit owner request can change them; update the relevant section here when that happens, rather than appending a contradictory rule at the end.

Give the next model the complete `site/` source folder, including `public/`, `src/`, `scripts/`, package files, and this document. This document specifies the design contract; it cannot reproduce proprietary font binaries, photos, certificate scans, or the exact signature SVG paths by itself. Do not approximate missing assets or rebuild this portfolio from a generic template. Preserve supplied assets and shared components. Paths below are relative to `site/` unless stated otherwise.

The site is static HTML generated by Node ES modules, with native CSS/JavaScript interactions. It is not a React, Next.js, Tailwind or GSAP project. Do not introduce those frameworks just to add content. Edit source, never generated `dist/` files. No API keys, remote fonts, analytics or backend are required.

### Non-negotiable current behavior

- Homepage: exactly the first two featured projects and first three sorted experience records; keep the existing section order.
- Projects have individual `/projects/<slug>/` pages. Certificates do **not** have individual pages.
- Certificates appear as separate non-clickable cards on `/certificates/`. Homepage marquee links go to `/certificates/#<slug>` and scroll to that card.
- Projects and Certificates start in grid for a fresh session. Grid button is first. Both share `sessionStorage['edwin-collection-view']`; list/grid choice survives navigation, refresh and cached history within the session.
- No project/certificate sorter. Keep search, `/` shortcut, result count and empty state.
- Project cards are static previews with hover lift; project detail galleries use manual horizontal slides and a viewport-filling viewer. No project autoplay.
- Certificate marquee keeps its continuous movement, drag momentum, pause and keyboard controls.
- Image frames and hover tiles have no decorative border. Hover tiles also have no drop shadow or colored backing rim. Preserve rounded clipping, hover motion and accessible keyboard focus.
- Keep both themes, reduced motion, responsive behavior, local assets, and the current typography. Do not invent reports, teammates, links, results or certificate credentials.

## Adding, editing and rearranging projects

### Add a project

1. Add one object to the exported `projects` array in `src/content/projects.mjs`. Use a unique stable lowercase hyphenated slug. There is no `published` filter for projects: every array entry is published and gets a page.
2. Place supplied images in `public/assets/projects/<slug>/`. Use stable descriptive filenames, meaningful alt text and actual pixel dimensions. Keep original proportions; the shared components handle display cropping. Add a supplied report under `public/documents/` if applicable. Never use a local Windows path or temporary attachment path as a public URL.
3. Provide the content fields shown below. Use `null`/omit unavailable optional resources. Keep `sections` and `stack` arrays present. Claims must distinguish implemented, simulated, reported and planned work.
4. Set `featured` deliberately. The homepage uses `projects.filter(p => p.featured).slice(0,2)`: a third featured entry does not automatically appear on home. Do not increase the two-card limit.
5. Build and run the checks. Confirm collection, detail, next-project navigation, image order, main-page selection and both themes. No manual HTML route or sitemap edit is needed.

Example record (replace example values before publishing):

```js
{
  slug: 'example-project',
  title: 'Example Project',
  fullTitle: 'A concise expanded title',
  category: 'Software development',
  featured: false,
  year: '2026',
  status: 'Working prototype',
  role: 'Describe the actual contribution',
  summary: 'A short, factual summary for cards and the detail overview.',
  stack: ['Python'],
  repository: null,
  demo: null,
  // demoLabel: 'Watch prototype',
  // document: '/documents/example-project-report.pdf',
  images: [
    {src: '/assets/projects/example-project/main.png',
     alt: 'Describe what the supplied screenshot shows.', width: 1536, height: 864}
  ],
  teammates: [],
  sections: [{title: 'What it does', body: ['Describe supported functionality.']}]
}
```

Optional teammate shape: `{name: 'Full Name', url: 'https://www.linkedin.com/in/verified-profile/'}`. Omit `url` when unverified; the detail template renders plain text. Optional narrative metric shape: `metric: {value: '...', label: '...', note: 'Qualification and evidence'}` inside a section. Do not invent measurements.

### Image precedence and ordering

- `images[0]` is the first project detail image. Rearrange the `images` array to change gallery order.
- The collection/grid/list-hover preview uses `previewImage || images[0]`.
- Homepage uses `homeImage` when supplied, otherwise `previewImage || images[0]`.
- Overrides are full `{src, alt, width, height}` objects, not strings. Do not accidentally replace a grid preview when the request only changes the detail gallery.
- No supplied images: omit/empty `images`; the shared card uses its explicitly labelled schematic fallback (`visual`, or `code`). Use only keys actually supported by `visuals.mjs`. Do not present a schematic as a screenshot.
- Keep real-image hover lift; replacing placeholder art must not remove the animation classes.

### Reorder, feature or remove projects

Move whole objects within the `projects` array. Array order controls collection order, default search tie order, Study numbering, next-project links (wrapping at the end), and the order of featured homepage candidates. To feature a new project first or second, place it accordingly among `featured: true` entries. To remove a project, remove its object; rebuild to remove its generated route and sitemap entry. Preserve stable slugs for existing projects unless a URL change is explicitly requested. `components.mjs` has slug-specific award labels that can override `status` on cards; check that helper when changing an existing achievement label.

Remove unused published assets from `public/` or archive them outside `public/` after confirming they are unreferenced. Do not delete source evidence merely to pass an asset-use check. Never restore previously removed projects from old snapshots.

## Adding, editing and rearranging certificates

### Add a certificate

1. Add a record to `profile.certificates` in `src/content/profile.mjs`. Preserve the JavaScript exports after the profile object; this file is not a standalone JSON file.
2. Use an explicit stable unique `slug`, so changing the title does not break homepage anchors. The current normalizer can derive a slug from the title, but new entries should supply one.
3. Copy the **certificate itself** to `public/assets/certificates/<slug>/certificate.png` (or another supported image extension). Use it as `image`. Do not use event photos, winner posters, team photos or logos as the main certificate preview.
4. Supply a short factual `description`, `title`, `type`, issuer/date if known (use `null` for an unknown date), image `width`/`height`, a `group` and numeric `priority` as described below, and `published: true`. `published: false` hides a draft from both surfaces. Do not copy draft-only assets into `public/` until used, because the checker rejects unused assets.
5. Build. The record automatically appears in the collection; only non-portrait records appear in the homepage marquee. Verify its homepage link lands at its matching collection card. Do not add a route, page template, modal, PDF action or clickable title/image.

```js
{
  slug: 'example-certificate',
  title: 'Exact certificate or achievement name',
  type: 'Achievement',
  issuer: 'Verified issuer',
  date: '6 September 2026',
  description: 'One or two factual sentences about the achievement.',
  image: '/assets/certificates/example-certificate/certificate.png',
  width: 1800,
  height: 1273,
  group: 'ibm',
  priority: 50,
  published: true
}
```

Current cards render title, type, date, description and image. Issuer participates in search but is not separately printed on the card. `image` is a URL string; certificate `images` arrays are **not** used by the current collection. Legacy `pdf`, `url`, `teammates` and `images` fields may remain in old data as evidence, but are not rendered. Adding those fields does not create a download/source action. Certificate PDFs and extra event photos belong in non-public source archives unless the owner explicitly requests a new visible use. Older requests for LinkedIn/Credly buttons, teammate sections, adaptive detail galleries and “View certificate as PDF” were superseded by removal of all certificate detail pages.

Without `image`, the existing system generates a labelled placeholder; never imply it is a genuine credential. Prefer a real certificate image for new published entries. Landscape certificate previews fill their frames. Portrait grid previews retain natural proportions without cropping; list-hover previews contain the full artwork with theme-adaptive backing (`var(--surface)`: `#192B21` in dark theme, `#D9E4D2` in light theme) in both grid and list-hover previews. Cards are non-clickable, without a link arrow, pointer cursor or fullscreen action. The homepage marquee alone provides links, using `/certificates/#<slug>`.

### Reorder or remove certificates

Ordering is explicit editorial metadata, shared by the collection and homepage marquee through `src/templates/certificate.mjs`. Set `group` and `priority` on every new record. Lower numeric priority appears first within a group; array order only breaks ties. Moving an array record alone does not override these fields. Keep priorities spaced (10, 20, 30...) for insertion. These are the owner's presentation preferences, not an objective ranking of institutions.

The `certificateGroups` array defines this order:
1. `awards`: competition wins first, then institutional selections. Innovare 2026 First Place precedes IDEATHON 2026 Second Place, then SIH institutional selection. Do not describe selection or participation as a national win.
2. `nptel`: keep Elite credentials together; the 12-week Java algorithms course precedes the 8-week DBMS course.
3. `honours`: Director's honours before Principal's honours; keep semester credentials separate.
4. `internships`: completion certificates, including Infosys PaperIQ and NeST Data Science. This category takes precedence over issuer grouping.
5. `ibm`: Quantum Excellence, Basics of Quantum Information, AI Fundamentals, Getting Started with AI.
6. `aws`: Braket Application Development and Braket Getting Started together, then Cloud Foundations (20 hours), Generative AI Foundations and database introduction.
7. `infosys`: other Infosys course completions together.
8. `oracle`, `google`, `kaggle`, `anthropic`, `intel`, `dubai`, `hackerrank`, `nasa`, `other`: keep each issuer's related credentials adjacent. NASA participation certificates stay together and are not winner awards.

Add a new issuer group to `certificateGroups` deliberately when needed. Unknown groups fall last; omitted priority defaults to 100. Within each group, use verified level, course depth and related subject sequence to choose priority; never invent prestige, scores or completion dates. Certificate search filters this order without relevance re-ranking; project search retains its existing relevance behavior.

Keep a stable slug while changing title, image or position. Homepage links and collection IDs are generated from the same normalized record. Hide with `published: false` or remove the record when asked; clean up unused public assets without destroying originals. Placeholder filenames use original array indices, so let the build generate them rather than manually renaming placeholder SVGs.

The catalogue currently contains 32 records, all with real previews. The Freedom with AI Masterclass placeholder has been removed. Innovare uses the replacement high-resolution Certificate of Appreciation supplied on 29 October 2026. Intel AI Appreciate precedes AI Aware within the Intel group; they are distinct stages. The duplicated Intel AI Aware attachment is represented once. Existing IDEATHON event photos remain unpublished; do not restore a gallery from retained metadata.

### PDF and image preview parity

Every visible certificate uses an ordinary local image in exactly the same card, list-hover preview and marquee, regardless of the original file format. Never embed PDFs, add PDF badges, browser PDF toolbars, downloads, new detail routes or a different visual treatment for PDF originals.

Archive original PDFs in `assets/source/certificates/` (outside `public/`). Render the certificate page into `public/assets/certificates/<slug>/certificate.png`, preserving the original artwork and text. The current eight PDFs are single-page documents, rendered with Poppler using `pdftoppm -f 1 -singlefile -scale-to 1800 -png INPUT OUTPUT_WITHOUT_EXTENSION`. For future multi-page files, inspect the pages and choose the actual certificate page rather than blindly choosing page one. Visually inspect the render, record its actual pixel dimensions, and use that PNG as `image`. Do not recreate the credential with HTML or AI-generated artwork.

Orientation is derived in `certificate.mjs` from image dimensions: `height > width` means portrait, including rendered PDF pages. Always record actual dimensions for either format. Portrait grid images use the same fixed 3:2 frame as landscape images, with object-fit: contain and centered natural proportions inside it; never let portrait intrinsic height enlarge the grid card. Use theme-adaptive backing (`var(--surface)`: `#192B21` in dark theme, `#D9E4D2` in light theme) in both grid and list-hover previews. List-hover images also use contain. Landscape images retain filled 3:2 frames. The homepage marquee excludes portraits using this same derived flag; they remain available in the collection. Never infer orientation from file extension or title. Keep the full uncropped asset on disk. Loading is lazy with reserved dimensions in collection cards. Verify images have decoded before taking screenshots; a screenshot captured immediately after filtering can precede lazy image decoding. Preserve both themes, border-free image hover, session view persistence and the existing animations.
